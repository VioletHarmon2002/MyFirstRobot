# Learning journal

## Scrum
During this project, I have delved into Scrum, which has significantly enhanced my approach to project management and execution. Scrum, an agile methodology, is designed to deliver high-value products through iterative development cycles called sprints.

#### Epics:
During scrum, I learned to make use of epics. An epic is a requirement that can be divided into user stories. This structure ensures that all related user stories are connected, providing a comprehensive view of the larger requirement and facilitating better tracking and management of progress.

#### User stories
Furthermore, I have also learned about creating and using user stories within Scrum. User stories are simple descriptions of a feature, written from the end user's perspective. They follow a specific format: `As a user, I want [an action] so that [a benefit/a value]`.

Using this format has streamlined the process of defining user stories, making them clear, actionable, and focused on user value. This approach has enabled me to complete more user stories than before, thereby improving both the efficiency and effectiveness of my work.

#### Vertical Slices
Working in vertical slices is another aspect I have learned during Scrum. A vertical slice refers to implementing a feature in a way that spans all layers of the project (from front-end, back-end, to embedded) instead of focusing on one layer at a time.

This approach has enabled me to contribute to multiple aspects of the project, giving me a broader understanding and ensuring that each feature is functional for the user.

## Gitlab
Besides Scrum, I have also learned to work with GitLab. We used GitLab to manage the product backlog, track the progress of user stories, and to see which ones were ready for review and which ones were completed. This made it much clearer for me to work on the project. Additionally, I have learned to work in different branches. This provides benefits such as isolated development of new features or bug fixes without impacting the main code, thereby promoting stability and collaboration within the team.

## Communication between robot and webserver
During this project, I worked on setting up communication between the web server and the robot. The communication flows from the front-end to the API, which sends it via the websocket server to the robot. I learned how to set up the API during the individual project. Setting up the websocket server was a new challenge for me. Initially, I had to write a script for this purpose. Even after doing this, the communication still didn't work. It was then that I realized I also needed to open the correct port on the server. Additionally, I managed to ensure that the robot automatically connects to the web server upon startup.
